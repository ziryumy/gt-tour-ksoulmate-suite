# HANDOFF-PROMPT.md — Antigravity에 붙여넣을 프롬프트

## 사용법

1. 이 폴더를 새 저장소 루트에 둡니다 (`AGENTS.md`가 루트에 있는지 확인)
2. Antigravity를 열고 **1단계** 프롬프트를 붙여넣습니다
3. 결과를 확인하고 **2단계**, 그다음 **3단계**
4. 각 단계 끝에서 **검증 프롬프트**로 자체 점검을 시킵니다

> **한 번에 다 시키지 마세요.** 에이전트형 IDE는 컨텍스트가 길어지면 앞의 결정을 놓칩니다.
> 한 단계가 통과해야 다음으로 갑니다.

## ⬛ 1단계 — 스캐폴드 + 데이터층

```

먼저 AGENTS.md, SPEC.md, DECISIONS.md를 끝까지 읽어라. 읽은 뒤 요약하지 말고 바로 작업해라.

[이번 단계 범위]
M1만 한다. 화면은 만들지 않는다.

1. Next.js 15 (App Router) + TypeScript strict + Tailwind + shadcn/ui 로 스캐폴드
2. Prisma 설치, SPEC.md 3장의 스키마를 prisma/schema.prisma 에 그대로 옮겨라
   - 모델명·필드명·enum 값을 바꾸지 마라
3. npx prisma migrate dev --name init
4. prisma/seed.ts 작성:
   - data/members.json, channels.json, episodes.json, budget.json, kpis.json, compliance.json 을 읽어 적재
   - idempotent 하게 (upsert 사용). 여러 번 실행해도 중복이 생기면 안 된다
   - data/ 폴더의 값은 절대 수정하지 마라
5. package.json 에 스크립트 추가: "db:seed": "tsx prisma/seed.ts"
6. app/(console)/dashboard/page.tsx 에 임시 페이지 하나만:
   - "Members 5 · Episodes 12 · Channels 4" 처럼 DB 실제 건수를 출력

[금지]
- UI 컴포넌트를 예쁘게 만들지 마라. 이번 단계는 데이터가 들어갔는지만 확인한다
- data/*.json 을 편집하지 마라
- 로그인·결제·AI API 호출을 넣지 마라

[완료 조건]
npx prisma migrate dev 와 npm run db:seed 가 에러 없이 끝나고,
/dashboard 에서 Member 5건 / Episode 12건 / Channel 4건이 확인된다.

작업이 끝나면 실행한 명령과 결과를 한 줄씩 보고해라.
```

## ⬛ 3단계 — 쓰기 + 규칙 엔진 + 게이트

```
SPEC.md 4.3 상태 전이, 4.5 채널 편집, 4.6 크레딧, 4.7 컴플라이언스, 4.8 참여, 5장 규칙 엔진을 구현해라.

[핵심 1 — 단계 이동]
에피소드 상태 변경은 버튼(◀ 이전 / 다음 ▶)과 드롭다운 두 가지로만 제공한다.
드래그 앤 드롭은 절대 넣지 마라. 사용자가 명시적으로 금지한 사항이다.

[핵심 2 — 채널 편집 화면]
/episodes/[no]/channels/[code] 를 만든다.
섹션 순서는 Channel.workflowOrder 를 따라 동적으로 배치해라.
  JP: 나레이션 대본 → V.O. → 편집 호흡 → BGM → 자막 → 발행
  US: BGM → 컷(편집 호흡) → V.O. → 자막 → 발행
  KR/CN: 자막 → 편집 호흡 → V.O. → BGM → 발행
편집 호흡에서 컷 수와 총 길이를 입력하면 평균 컷이 실시간 계산되어 표시된다.
규격(±0.3초)에서 벗어나면 인라인 경고. 단 저장은 막지 않는다. 발행만 막는다.
고정 항목(베이스 영상·오늘의 표현·캐릭터 시트)은 읽기 전용 패널로 분리하고 "고정" 라벨을 단다.

[핵심 3 — 발행 게이트]
lib/rules/compliance.ts 에 canPublish(episode) 를 구현.
활성 채널 중 DONE 이 아닌 것이 있거나, blockAt=BEFORE_PUBLISH 항목이 미완료면 false.
차단 시 사유를 구체적으로: "미완성 채널: US, KR / 미완료 검수: JP-04"
3·6·7화는 약기법 항목이 필수. 해당 회차에서는 회색 처리도 불가.

[핵심 4 — 나머지]
- /credits: 게이지(80% 주황, 90% 빨강), 회차별 소모 표, 채택률 75% 미만 행 강조
- /compliance: 7항목 × 12화 매트릭스 체크박스
- /engagement: 응원 게이지 / 팬덤명 후보(5개 검사 전부 통과해야 SHORTLIST 가능) / 미션 회수
- 대시보드 경고 배너에 실제 조건 연결 (미완성 채널 / 크레딧 90% / 컴플라이언스 미완료)

[금지]
- AI 생성 API 호출 금지. 크레딧은 수동 입력이다
- 매출 목표 달성률 위젯을 만들지 마라 (DECISIONS.md A-4 참조)
- 자동 번역 기능 금지

[완료 조건]
AC-07 ~ AC-14 통과. npm run build 통과. TypeScript 에러 0.
```

## 참고 — 왜 이렇게 나누는가

에이전트형 IDE에 이 프로젝트를 한 번에 시키면 흔히 이렇게 실패합니다.

| 흔한 실패 | 이 키트의 대응 |
|---|---|
| 스키마를 지어냄 | SPEC.md 3장에 Prisma 스키마 전문을 넣어 그대로 옮기게 함 |
| 데이터를 하드코딩 | `data/*.json`을 유일한 소스로 지정, 수정 금지 명시 |
| 드래그 앤 드롭을 넣음 | AGENTS.md 2장 + 각 단계 프롬프트에 두 번 명시 |
| AI 생성 버튼을 만듦 | 비목표를 세 곳에 반복 기재 |
| "완료"라고 자기 보고 | 검증 프롬프트로 실행 결과만 보고하게 함 |
| 앞 단계 결정을 잊음 | 3단계로 분할, 단계마다 완료 조건 명시 |
